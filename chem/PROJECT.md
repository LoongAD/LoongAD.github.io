## 0. 一句话背景

用户要做一个**初中化学虚拟实验平台**，对标 `huajianlab.cn`（化见实验室），**除登录注册和商业化外尽可能复刻全套**。个人使用，不公开、不收费。

目标用户：初中化学教师（课堂演示 / 备课）。

产品形态：首页（营销）→ 实验库（章节树）→ 实验详情 → 交互实验室。

## 2. 五条核心结论（最重要，别错过）

### 2.1 宣传图 ≠ 实际效果

首页那张 `free-lab.webp` 是**精修渲染图**（写实玻璃、摄影棚打光）。实际界面：

- 「仪器识别」实验：**扁平 SVG 线条**，没有质感
- 「中和反应」实验：简单渐变 + 一层高光的锥形瓶

**不要拿宣传图当验收标准。**

### 2.2 它没有物理引擎

中和反应实验底部原话：

> 克数、浓度与每滴 0.20 g 为教学模型参数，并非教材指定用量；**液面按 1 g/mL 示意，不表示真实密度**。

即：液面 = 质量 × 1 mL/g（线性），反应 = 化学计量算完改数字和颜色。**没有粒子、没有流体、没有碰撞。**

**结论：复刻不需要 Matter.js / Three.js。**

### 2.3 三种实验形态，没有一个是模拟器

| 形态 | 实例 | 本质 |
|---|---|---|
| 分类拖拽题 | `U1-04` 仪器识别：5 个分类框 + 11 个器材 | 拖拽 + 判定对错 |
| 参数化操作 | `D10-11` 中和反应：左参数 → 确认投料 → 滴加 → HUD 变化 | 表单 + 状态机 + 化学计算 |
| 自由沙盒 | `/free-lab`：15+ 器材、三 tab（容器/工具/化学物）、撤销重做 | 自由摆放 |

### 2.4 舞台结构（中和反应，可当模板）

```
┌ 顶栏 68px：返回 / 实验名 / 教学辅助 / 帮助 / 全屏 / 账号
├ 左侧 260–280px（tab：器材 / 条件）
│   ├ NaOH 溶液质量：10g | 20g
│   ├ NaOH 质量分数：1% | 2%
│   ├ 稀盐酸滴管装液：1g | 5g | 10g
│   ├ HCl 质量分数：5% | 10%
│   ├ 确认本轮克数：[未确认] → 确认投料
│   ├ 滴加酚酞：每次 0.02 g
│   ├ 逐滴加入稀盐酸：每次 0.20 g
│   ├ 连续滴加到限量上限
│   └ 记录中和结论：[未记录]
├ 中间 WebGL canvas
│   ├ 中央锥形瓶（液面随质量变化）
│   ├ 两侧可拖拽滴管（酚酞 0.12g / 稀盐酸 10.00g）
│   └ 4 个 HUD 框：反应式 / 离子式 / 剩余 OH⁻ / 新增 H₂O + H⁺ 过量
└ 底部 44px：重置 / 撤销 / 暂停 / 0.5× 1× 2× / 现象
```

### 2.5 真正值钱的是 HUD

老师愿意付费的不是动画，是那几个数字：**剩余 OH⁻、生成的水、H⁺ 是否过量**——因为考试要考。

**做产品时，数据反馈的优先级高于视觉效果。**

### 2.6 交互有前置校验

没点「确认投料」就点「滴加」，底部提示 **「当前操作不可执行」**。这是教学设计（逼学生先定量再操作），值得保留。

### 2.7 每个实验都是独立设计（这条最容易做错）

不是"一张台面换参数"，是**每套界面单独设计**。证据在 `ref/` 里，横着比一遍就很明显：

已通过面板特征 + 截图确认，32 个实验归为 **11 种形态**（不是 32 种，也不是 1 种）：

| # | 形态 | 代表 | 舞台构成 | 交互重心 |
|---|---|---|---|---|
| 1 | 分类拖拽题 | `U1-04` | 5 个分类框 + 11 件器材 | 拖到对应分类 |
| 2 | 单器材数值投料 | `U2-03` | 集气瓶 + 铁丝 + 火柴 + 烧杯 | 两个数值框（0.56g / 0.32g）+ 拖入瓶 |
| 3 | 多器材容量流动 | `U4-02` | 6 件器材同台 | 容量在器材间转移（95g → 截留 / 滤液） |
| 4 | 装置/电路 | `U4-06` | 电解槽 + 双收集管 + 电源 + 导线 | 通电、观察 2:1 体积比 |
| 5 | 测量比色 | `D10-02` | 三孔比色板 + 可拖试纸 + 色阶 | 拖试纸逐个接触、比色 |
| 6 | 多组对照矩阵 | `D8-04` | 4 组并排，每组 4 个数值框 | 并排比较 12 个实时数值 |
| 7 | 参数锁定 + HUD | `D10-11` | 锥形瓶 + 双滴管 + 4 个 HUD 框 | 数值联动（OH⁻ / H₂O / H⁺） |
| 8 | 多步分离 | `D9-10` | 溶解→过滤→蒸发串联 | 步骤推进 |
| 9 | **路线对比** | `U2-05` | 两套装置并排（加热 / 常温） | 选路线 → 选发生装置 → 对比产率 |
| 10 | **配制计算** | `D9-05` | 天平 + 药匙 + 量筒 + 烧杯 + 试剂瓶 + 公式卡 | 先算后称，逐步确认 |
| 11 | 结论记录 | `D10-06` | 常规装置 + 记录面板 | 做实验 → 填结论 |

**共同点只有三个**：左侧参数面板、中间舞台、底部控制条。其余全是各做各的。

> 形态 9、10 最容易被漏掉——`U2-05` 有「第一步·选择反应路线 / 第二步·选择发生装置」的分步向导，`D9-05` 有质量分数公式卡 + 托盘天平。这两个只看面板数据不够，必须看截图。

### 3.1 关于「操作流程」的说明

已抓到的是**控件级**数据（有哪些参数、按钮的两种状态），**不是流程级**（正确顺序、每步反馈、完成判定）。

原因：真正的实验动作发生在 canvas 舞台上（拖铁丝进集气瓶、点酒精灯），而这部分无法用自动化模拟（见 §8 第 7 条）。左侧按钮只是"准备"，点完只回一句「实验过程已更新」。

**但流程不需要抄**：教学实验的步骤由教材和化学逻辑决定，不是竞品的独创。例如铁丝燃烧的标准流程是「瓶底加水 → 点燃火柴 → 点燃铁丝 → 伸入集气瓶 → 观察火星四射」，这在你手上的教材里就有。

复刻时建议：**参数和控件照它的，流程按教材写**。

### 6.1 原型的实现要点

- 纯 HTML + CSS + 原生 JS，无构建
- 器材用 **SVG 绘制**（`GEO` 存 clip path + outline）
- 状态：`state.vessels[]` + `REAGENTS[]` + `RULES[]`
- 反应：`pair:['cuso4','naoh']` 命中后变色/沉淀/冒泡
- **增量渲染**：`render()` 只更新属性不重建 DOM，否则液面过渡和气泡会消失
- 内置 5 个反应：CuSO₄+NaOH 沉淀、Na₂CO₃+HCl 气泡、酚酞+NaOH 变红、2 个对照

**它缺的正是 HUD 层。**

## 8. 复现竞品观察的方法（硬知识）

```python
# 1) 登录是 modal，不是 /login（该路径 404）
#    首页导航点「登录」→ 邮箱 + 密码

# 2) 输入框带 readonly（防自动填充），fill() 会超时！
pg.locator("input[type=email]").click()
pg.keyboard.type("邮箱", delay=30)      # 必须先 click 再 type

# 3) 舞台是 WebGL，headless 一定失败：
#    "Flaskora stage initialization failed"
#    必须用有头 + Xvfb + SwiftShader：
#    $ xvfb-run -a python3 script.py
b = p.chromium.launch(headless=False, args=[
    "--no-sandbox", "--use-gl=swiftshader",
    "--enable-unsafe-swiftshader", "--disable-dev-shm-usage"])
# 4) 舞台加载慢（软件渲染），等 15–18 秒

# 5) 实验 URL 是 /lab/<编号>，不是 slug
# 6) 按钮在左侧滚动区，用 get_by_role("button", name="...")

# 7) ⚠️ 左侧面板按钮常在滚动区外
#    bounding_box() 返回的是文档坐标，未滚动时 click 会点到空处。
#    必须先 scroll_into_view_if_needed() 再 click()，且不要加 force=True
#    （force 会跳过可操作性检查，导致"点了没反应"）。
loc.scroll_into_view_if_needed()
loc.click()

# 8) ⚠️ canvas 内部的拖拽（把铁丝拖进集气瓶这类）无法用 mouse 模拟
#    试过 U1-04 与 U2-03，drag 后舞台纹丝不动。原因大概率是自研引擎
#    用 pointer capture + 自定义命中检测，Playwright 的 mouse 序列不被识别。
#    结论：操作流程只能人工点着看，别在自动化上耗时间。
```

**凭据不要写进任何文件**，需要时向用户索取。
